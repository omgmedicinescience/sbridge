# cBridge

cBridge — сертификационный шлюз для входящего и исходящего контента Айдадок.
Он выбирает нужные Markdown-политики, минимизирует данные, передаёт контент
одобренному AI evaluator и возвращает формальное решение:

- `allow` — контент соответствует политикам;
- `block` — контент нельзя пропускать;
- `review` — нужна ручная проверка или недоступен безопасный evaluator;
- `sanitize` — можно использовать только предложенную безопасную версию.

## Что уже готово

- формат контекстных `.md`-политик;
- компилятор политик в неизменяемый JSON bundle;
- версионированный контракт решения;
- минимизация email, телефонов, токенов и распространённых секретов;
- ядро сертификации с timeout и fail-modes;
- provider-neutral AI adapter contract;
- OpenAI Responses API adapter со строгим Structured Output;
- baseline evaluator только для разработки и тестов;
- Cloudflare middleware-заготовка;
- тесты основных безопасных и опасных сценариев.

## Что cBridge проверяет

cBridge предназначен для content-bearing транзакций:

- сообщения пользователя;
- JSON/text API payloads;
- ответы ассистента или системы;
- человекочитаемые ответы web/API;
- контент, уходящий во внешние интеграции.

CSS, шрифты, изображения и другие статические файлы не отправляются в ИИ при
каждом запросе. Они должны проходить build-time проверку и публиковаться по
checksum.

## Быстрая проверка

```bash
cd cBridge
node scripts/build-context-bundle.mjs
node --test tests/*.test.mjs
```

## Важный статус

cBridge подключён к production Worker только для закрытых тестовых маршрутов
`POST /api/cbridge/test`, `POST /api/cbridge/evaluate` и
`POST /api/cbridge/diagnose` и работает в режиме `observe`. Последний маршрут
сопоставляет описание симптомов с 49 архивными схемами книги
`data/aidadoc-symptoms/flowcharts.md` локально и не передаёт медицинский текст во
внешний AI. Для демо вручную сверены с PDF восемь графов большой книги: слабость,
потеря веса, высокая температура, головная боль, головокружение, охриплость,
нарушение дыхания и кашель. Переходы между этими схемами исполняются, а все
подходящие книжные заключения сортируются по срочности. Дополнительная подробная
разметка старой книги сохранена в `data/aidadoc-serdce/flowcharts.md`, но в этом
демо не активируется. Результат маршрута является демонстрационным разбором,
а не диагнозом или клинической рекомендацией.
Статические файлы сайта не отправляются в ИИ. Медицинские и персональные данные
для OpenAI evaluator не разрешены.

Перед подключением продуктовых маршрутов нужны:

1. решение о допустимой передаче медицинских данных;
2. D1 audit storage;
3. golden-набор тестовых запросов;
4. отдельное подтверждение перехода в `enforce`.

Полная схема подключения описана в `ARCHITECTURE.md`.
